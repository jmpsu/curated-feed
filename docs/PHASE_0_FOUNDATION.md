## Architecture Decisions Implemented

### Database Schema
- **Normalization:** Single `content` table with flexible JSON fields for heterogeneous media
- **Vector Storage:** pgvector embeddings in `content.embedding` (384 dimensions)
- **Denormalization:** Pre-computed fields (reading_time, word_count) for ranking efficiency
- **Deduplication:** content_hash + is_duplicate + original_content_id for tracking duplicates

### Tagging Strategy
- **User-Generated:** Separate arrays for system-generated vs user-added tags
- **Tag-Based Filtering:** Efficient JSON arrays with O(N) filtering (N = tags per item)
- **Future Optimization:** Can migrate to separate `content_tags` table if tag cardinality grows >10K

### Ingestion State
- **Cursor Management:** `last_cursor` supports API pagination (Twitter's next_token, etc)
- **Backoff Strategy:** `consecutive_failures` + `retry_backoff_ms` for exponential backoff
- **Rate Limiting:** `last_fetch_time` and `next_retry_at` for scheduling discovery

### Environment Configuration
- **Dev/Staging/Prod:** Separate D1 databases per environment via wrangler.toml
- **R2 Buckets:** Isolated media storage per environment (no cross-environment contamination)
- **Local Testing:** D1 local emulation for development without Cloudflare account

## Schema Assumptions

### Content Types Supported
- `article` - Long-form text with optional poster image
- `video` - YouTube, embedded video, or podcast
- `image` - Single image with caption
- `tweet` - X/Twitter post (280 chars + media)
- `instagram_post` - Instagram photo/carousel/reel
- `reddit_post` - Reddit link or text post
- `news` - News aggregator item from RSS

### Embedding Model
- Default: `all-MiniLM-L6-v2` (384-dimensional, fast inference)
- Switchable via `embedding_model` field per content item
- Supports 0-shot and few-shot learning scenarios

## Known Limitations

1. **pgvector Not Available on D1:** Cloudflare D1 is SQLite-based, not PostgreSQL
   - **Impact:** Vector search will use application-level similarity (numpy/WASM)
   - **Mitigation:** Store embeddings as BLOB, compute similarity in Workers
   
2. **No Native JSON Indexing:** SQLite's JSON is slower than PostgreSQL
   - **Impact:** Tag filtering will do full table scans initially
   - **Mitigation:** Add separate `content_tags` table if >100K items

3. **No Full-Text Search:** SQLite FTS not configured yet
   - **Impact:** Title/description searches are substring-only
   - **Mitigation:** Add FTS5 virtual table in Phase 1 if needed

## Future Migrations

As the system grows:
1. **Phase 3:** Add `content_tags` table for normalized tag storage
2. **Phase 5:** Add `content_vectors_index` table for efficient similarity search
3. **Phase 8:** Add `ingestion_logs` table for audit trail
4. **Production:** Migrate from D1 to managed PostgreSQL + pgvector
